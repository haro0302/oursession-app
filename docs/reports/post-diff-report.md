# 投稿ページ 実装差分レポート

> 現在の実装スクショ(投稿ページ idle / 楽曲追加時)と、プロト(`our-session-modern.html`)・仕様書(`post-screen-spec.md`)を比較した結果。
> Claude Code は**すべて**を修正すること。

---

## ❌ 致命的な問題

### 問題1: 投稿ページが「ドロワー」になっている

**現状**: 投稿が**下からスライドアップする半透明のドロワー**として実装されている。
- 上部にハンドル(横線)あり
- 背景の「テストウエガキ」などのテキストが透けて見える
- 「音源を投稿する」タイトル + ×ボタン

**正解**: 投稿は**独立したページ(Screen)**。タイムラインや マイページと同じ階層。
- URLが変わる(または変えない場合もあり、ただしページとして扱う)
- ハンドル無し
- ×ボタン無し(代わりに「キャンセル」テキストボタン)
- 背景は透けない(タイムラインのカードが見えない)
- ボトムナビは表示される(他の画面に切り替えられる)

**修正アクション**:
- ボトムナビ中央の➕タップで、Drawer ではなく **画面遷移**するように変更
- `<dialog>` や `<Drawer>` コンポーネントではなく、ルート/タブ画面として実装
- React Router 等を使うなら `/post` パスへ遷移

**仕様書参照**: `post-screen-spec.md §0, §1`

---

### 問題2: ヘッダーの構成が違う

**現状**: 「音源を投稿する | ×」の2要素

**正解**: 「キャンセル | 新しいセッション | 公開」の3要素

```
左:   [キャンセル] ← テキストボタン
中央: 新しいセッション ← タイトル
右:   [公開]    ← 必須項目入力後に赤くなるボタン
```

**修正**: ヘッダー構造を完全に書き換える。詳細は `post-screen-spec.md §2`。

**「公開」ボタンの挙動**:
- 初期状態: 灰色、非活性
- 音源 + タイトル + タグ最低1つ揃ったら赤くなる(`.ready`)
- 赤い状態でタップ → 投稿実行 → タイムラインへ + 完了トースト

---

### 問題3: 安心ブロックが1つしかない

**現状**: 「🔒 公開範囲: 全員 / 足あとは残りません」の1ブロックのみ

**正解**: **2つの独立した安心ブロック**が縦に並ぶ:

```
┌─────────────────────────────┐
│ 👥(緑) 同じギター好きが        │  ← 孤独感解消(これが現在無い)
│        23人 いま探しています   │
│        あなたの投稿を待って... │
└─────────────────────────────┘

┌─────────────────────────────┐
│ 👁(琥珀) 公開範囲: 全員       │  ← 公開範囲明示(現在のものに近いが詳細違う)
│         足あとは残りません    │
│         アプリ利用者なら...   │
└─────────────────────────────┘
```

**現状で欠けている**:
- ❌ 孤独感解消ブロック(緑、users アイコン、「同じ○○好きが○人います」)
- ❌ 公開範囲ブロックのサブテキスト「アプリ利用者なら誰でも聴けます。誰が聴いたかは表示されないので、安心して投稿できます。」

**仕様書参照**: `post-screen-spec.md §3`

**重要**: CLAUDE.md §4「**必ず実装する安心装置**」のうち**2つを兼ねる**箇所。片方だけだと不十分。

### 問題4: 音源セクションのUIが控えめすぎる

**現状**:
- 「録音する」テキストの赤い大きなボタン(マイクアイコンが小さい)
- 「ファイルから選ぶ」は**フラットな細いボタン**
- 「MP3・5MB以下・90秒以内」のサブテキストが2つの真ん中にある

**正解**:
- **「その場で録音する」**(主役、大きい、サブテキスト「スマホのマイクで90秒まで」付き)
- 「── または ──」セパレータ
- 「ファイルから選ぶ」は**破線囲みの大きなドロップゾーン**(アップロードアイコン+「MP3 (90秒・5MBまで)」)

```
┌─────────────────────────────┐
│ 🎤(白の円) その場で録音する    │  ← 主役の赤い大ボタン
│            スマホのマイクで    │     左にアイコン、右にテキスト2行
│            90秒まで           │
└─────────────────────────────┘

       ──── または ────

┌╴╴╴╴╴╴╴╴╴╴╴╴╴╴╴╴╴╴╴╴╴┐
╎     ↑(赤の円)            ╎    ← 破線囲み、中央寄せ、大きい
╎     ファイルから選ぶ         ╎
╎     MP3 (90秒・5MBまで)   ╎
└╴╴╴╴╴╴╴╴╴╴╴╴╴╴╴╴╴╴╴╴╴┘
```

**修正点**:
- 録音ボタンのタイトルを「**その場で録音する**」に
- 録音ボタンにサブテキスト「スマホのマイクで90秒まで」を追加
- 「または」セパレータを追加
- ファイル選択を**破線囲みの大きなドロップゾーン**にリデザイン
- 個別にサイズ情報を併記(「MP3 (90秒・5MBまで)」)

**仕様書参照**: `post-screen-spec.md §4`

### 問題5: タグがカンマ区切りテキスト入力になっている

**現状**: 「タグ(任意・カンマ区切り)」というラベル + テキスト入力欄「ジャズ, ギター, 初心者歓迎」

**正解**: 「セッションアンサー希望」(**必須**・1つ以上) + 3カテゴリ別の「+追加」UI:

```
セッションアンサー希望        必須・1つ以上
┌──────────────────────────────┐
│ 楽器                  [+ 追加] │
│ 未選択                          │
│ ─────────                       │
│ ジャンル              [+ 追加] │
│ 未選択                          │
│ ─────────                       │
│ エリア                [+ 追加] │
│ 未選択                          │
└──────────────────────────────┘
```

**問題**:
- ❌ 「タグ」というラベル(正解: 「セッションアンサー希望」)
- ❌ 「(任意・カンマ区切り)」(正解: 「必須・1つ以上」)
- ❌ カンマ区切りテキスト入力(正解: フィルタシートで選択)
- ❌ ジャンル・楽器・エリアの区別が無い

**修正アクション**:
- カンマ区切りテキスト入力を**削除**
- 3カテゴリのカードを実装(楽器/ジャンル/エリア)
- 各「+追加」タップで**フィルタシート**(`filter-sheet-spec.md` 参照)を開く
- 選択結果はピル形式で表示、各×で削除可能
- フィルタシートはタイムラインのと**同じシートを再利用**(`currentContext = 'post'`)

**仕様書参照**: `post-screen-spec.md §8`、`filter-sheet-spec.md`

### 問題6: 「練習中(セッション歓迎)」トグルが投稿ページにある

**現状**: 投稿ページの下部に「練習中(セッション歓迎)」トグルがある。

**正解**: 投稿ページに**この設定は無い**。「練習中」フラグはプロフィール単位の設定であり、プロフィール編集ドロワーで設定する。

**理由**:
- 「練習中」は**ユーザー全体に紐づく属性**(その人が今練習中かどうか)
- 投稿ごとに切り替えるものではない
- 投稿に表示される練習中バッジは、**ユーザーの設定**を反映する

**修正**: 投稿ページから「練習中」トグルを**削除**。プロフィール編集ドロワーで設定する仕組みに。

---

### 問題7: 「投稿する」ボタンが下にある

**現状**: 画面下部に「投稿する」ボタン(灰色、非活性)がある。

**正解**: 投稿実行は**ヘッダー右の「公開」ボタン**。画面下部の「投稿する」ボタンは**不要**。

**修正**: 画面下部の「投稿する」ボタンを削除。投稿はヘッダー右の「公開」で行う。

## ⚠️ 中程度の問題

### 問題8: タイトルの placeholder が違う

**現状**: 「例: ジャズセッション相手を探しています」

**正解**: 「例: 山下達郎「Sparkle」コピー」

**理由**: より具体的で「やりたい曲」が伝わる例の方が、初心者が真似しやすい。

---

### 問題9: 本文のラベルが「ひとこと」になっている

**現状**: 「ひとこと(任意)」

**正解**: 「本文」(右側に「任意・150字以内」のサブテキスト)

**理由**: 「ひとこと」だと短い言葉を期待してしまう。実際は150字まで書ける。「本文」の方が自由度を感じられる。

---

### 問題10: 本文の placeholder

**現状**: 「どんなセッションがしたいか、気軽に書いてみてください。」

**正解**: 「どんなセッションがしたいか、どんな人を探しているかを書いてみよう。」

**理由**: 「どんな人を探しているか」も**重要な情報**(楽器・ジャンル以外の人柄など)。CLAUDE.md トーン「**そっと背中を押す**」の例にも合う「〜してみよう」。

---

### 問題11: 文字数カウンタの表示

**現状**: タイトル・本文に文字数カウンタが見えない

**正解**: 各入力欄の**右下に「0 / 30」「0 / 150」**のカウンタ。超えたら赤になる。

---

### 問題12: 必須マークの色

**現状**: 「タイトル *」のアスタリスクで必須を示している。

**正解**: ラベルの**右側に赤い必須テキスト**で表示:
- タイトル: 「**必須・30字以内**」(赤、太字)
- 本文: 「任意・150字以内」(text3、控えめ)
- 音源: 「**必須・90秒/5MBまで**」(赤、太字)
- セッションアンサー希望: 「**必須・1つ以上**」(赤、太字)

ラベルとサブテキストが**flex で左右に並ぶ**:

```html
<div class="post-label">
  <span>タイトル</span>
  <span class="post-label-req">必須・30字以内</span>
</div>
```
