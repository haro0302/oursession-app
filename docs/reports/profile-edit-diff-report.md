# プロフィール編集ドロワー 実装差分レポート

## ❌ 致命的な問題

### 問題1: アバター(写真)エリアが存在しない

**現状**: ドロワーが「ニックネーム」入力から始まる。アバター表示・変更機能が**完全に無い**。

**正解**: ドロワー上部に**大きなアバター(72×72px) + ニックネーム入力**が横並びで配置される。アバター右下にカメラアイコンの「変更」バッジ。

```
┌──────┐  ┌─────────────────────┐
│ 👤   │  │ ニックネーム            │
│      │  │ [ヨシキ                ]│
│  📷  │  │                         │
└──────┘  └─────────────────────┘
   ↑
アバター + 変更バッジ
```

**修正アクション**:
1. ドロワー最上部に `pe-avatar-block` セクションを追加
2. アバター画像表示(初期値は `user` アイコン)
3. 右下に小さな赤いカメラアイコンバッジ(`pe-avatar-edit`)
4. クリックでファイル選択ダイアログ
5. ニックネームを横並びで配置

**重要**: ニックネーム入力欄も同時に再配置(現状は単独で上にあるが、アバターと横並びにする)

**仕様書参照**: `profile-edit-spec.md §4`

### 問題3: 練習中トグルが場所違い

**現状**: 「練習中」トグルが**「好きなアーティスト」入力の下**に配置されている。

**正解**: 練習中トグルは**ニックネーム/アバターの直下**(ドロワーの上から2番目)に配置する。

**理由**: 練習中フラグはCLAUDE.md §4「**必ず実装する安心装置**」のひとつ。プロフィールで最重要な「私はこういう人」を表す情報なので、目立つ場所に置く。後ろに埋もれさせない。

**修正**: トグル要素をニックネームの直下に移動。

**仕様書参照**: `profile-edit-spec.md §5`

### 問題4: タグ選択UIが「個別チップ方式」になっている

**現状**: 楽器・ジャンルが「ピル状チップが並ぶ → 個別タップで選択」方式。

**正解**: **フィルタシート方式**(投稿ページ・タイムラインフィルタと同じ):
- 「+追加」ボタン → 下からフィルタシート → 複数選択 → 決定
- 選択済みは赤いピル + ×ボタン

```
好きな楽器・担当            複数選択可
[ボーカル ×] [ギター ×] [+追加]
                            ↑ タップでフィルタシート
```

**理由**:
- ユーザーのメンタルモデル統一(「タグ選択 = フィルタシート」)
- 楽器・ジャンルの選択肢が多くなっても画面が広がらない
- 投稿ページのコンポーネントを使い回せる

**修正アクション**:
- 既存のチップグリッドを削除
- `pe-tag-grid` (選択済みピル + 「+追加」ボタン)に置き換え
- 「+追加」タップで `openFilterSheet('instrument', 'profile-edit')` を呼ぶ
- フィルタシートの「決定」時に、context = 'profile-edit' なら profiles の楽器/ジャンルを更新

**仕様書参照**: `profile-edit-spec.md §7`

### 問題5: 好きなアーティストがカンマ区切りテキスト入力

**現状**: テキスト入力欄「例: Miles Davis, YOASOBI, くるり」

**正解**: 個別タグ追加方式:
- 「+追加」タップ → テキスト入力欄が表示 → Enter or 入力欄外タップで追加 → タグとして表示
- 最大10件まで
- 各タグに×ボタンで個別削除可能

```
好きなアーティスト         最大10件
[Miles Davis ×] [aiko ×] [+追加]
                            ↑ タップで入力欄表示
```

**修正アクション**:
- カンマ区切り入力を削除
- `pe-tag-grid` + サジェスト入力欄(`pe-suggest-wrap`)に置き換え
- Enter キーで追加、空文字は無視、重複も無視
- 最大10件、超えたら「+追加」非活性

**仕様書参照**: `profile-edit-spec.md §8`

### 問題6: 「好きな曲」セクションが無い

**現状**: 「好きなアーティスト」しかない。

**正解**: 「好きなアーティスト」とは**別**に「好きな曲」セクションがある。

```
好きなアーティスト         最大10件
[Miles Davis ×] [aiko ×] [+追加]

好きな曲                  最大10件
[Sparkle ×] [白日 ×] [+追加]
```

**理由**: 
- CLAUDE.md データモデルにある `favorite_tracks[]` を反映するため
- 「アーティストは好きだけど、特にこの曲が好き」を表現できる
- マッチング(似ている人スコアリング)でも `favoriteTracks` が高い重み(×3)で効く

**修正アクション**: 「好きなアーティスト」と同じ構造の「好きな曲」セクションを追加。

**仕様書参照**: `profile-edit-spec.md §8`、CLAUDE.md データモデル

**正解**: **47都道府県** + 「その他」のセレクトボックス。

**修正アクション**:

**仕様書参照**: `profile-edit-spec.md §9`

### 問題8: SNS連携セクションが無い

**現状**: SNS情報の入力が無い。

**正解**: X (Twitter) / Instagram / SoundCloud の3つの入力欄。

```
SNS連携                  任意
[𝕏] [X (Twitter) ユーザー名     ]
[📷] [Instagram ユーザー名      ]
[☁️] [SoundCloud ユーザー名     ]
```

**理由**: 
- CLAUDE.md データモデルの `sns_links` を反映
- マッチした相手にSNSで個別連絡したい場合がある
- 任意項目だが、入力できる場が必要

**修正アクション**: 3つの `pe-sns-row` を追加。各SNSのアイコン + ユーザー名入力。

**仕様書参照**: `profile-edit-spec.md §10`

### 問題9: 「保存」ボタンが下部にある

**現状**: ドロワー下部に独立した「保存する」ボタン(赤い大きな丸ボタン)。

**正解**: **ヘッダー右の「保存」ボタン**(他のドロワーと統一)。下部のボタンは無い。

**理由**:
- 投稿ページ・アンサードロワーと**操作パターンを統一**
- ヘッダーで完結することで、スクロールが必要なくなる
- 「キャンセル」と「保存」が左右対称で見やすい

**修正アクション**:
- 下部の「保存する」ボタンを削除
- ヘッダー右に「保存」ボタンを配置(`pe-header-btn.save`)

**仕様書参照**: `profile-edit-spec.md §3`

## ⚠️ 中程度の問題

### 問題10: インラインスタイル多用

**現状**: すべての要素に `style="..."` で直書きされている。

**正解**: CSSクラスを使う。CSS変数経由でデザイントークンを参照。

```html
<!-- ❌ ダメな例 -->
<input style="width: 100%; background: var(--card); border: 1px solid var(--border2); ..." />

<!-- ✅ 良い例 -->
<input class="pe-name-input" />
```

**理由**: CLAUDE.md §5「**色・余白・フォントをコンポーネントに直書き禁止**」。再利用性・保守性が悪い。

**修正アクション**: 仕様書のCSS定義に従って、スタイルをコンポーネント化。

**仕様書参照**: `profile-edit-spec.md` の各セクションのCSS
