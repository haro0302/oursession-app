# Claude Code 実装指示：セッションアシスト（お題デッキ ＋ スタジオ枠提案）

> `prototypes/our-session-cards-v2.html`（お題デッキ）
> `prototypes/our-session-studio.html`（スタジオ枠提案）
> を参照してください。

---

## 今回つくるもの

承認直後の部屋に置かれる **「セッションアシスト」**。
音楽の話から始めて、スタジオの予約確定までを1本の線で繋ぐ。

```
アンサー承認 → 個別部屋
   ↓
① お題デッキ（6枚）… 音楽を温めながら、場所と時間の大枠まで
   ↓
② スタジオ枠の提案 … ホストが実在の空き枠を最大3つ出す
   ↓
③ ゲストが1タップで選ぶ
   ↓
④ ホストが「スタジオを押さえた」→ 確定
```

---

## ① お題デッキ（6枚）

### カードの中身（この順番・この文言で）

| # | 質問 | 入力形式 |
|---|---|---|
| 1 | パートと音楽歴を教えて | パート＝**複数選択** ＋ 音楽歴＝**単一選択**（はじめたばかり / 1〜3年 / 3年以上 / だいぶ長い） |
| 2 | この曲のどこが好き？ | 自由記述 |
| 3 | セッションへの意気込みは？ | 自由記述 |
| 4 | 他にセッションしてみたい曲は？ | 自由記述 |
| 5 | スタジオ使ったことある？どのへん？ | 自由記述 |
| 6 | 動きやすいのはどのへん？ | **複数選択**（平日夜 / 週末昼 / 週末夜） |

- 1〜4が「温め」、5〜6が「段取り」。この**グラデーションが設計の肝**なので順番を変えない。
- 1枚目を選択式にしているのは、**指2タップで最初の1枚を抜けさせる**ため。ここで手が止まるとデッキごと死ぬ。
- マイページに書いてある「好きな曲・アーティスト」は**あえて聞かない**（重複するため）。

### 答え方（ここが最重要）

- 回答は**ドロワー（下から出るボトムシート）**で行う。既存の投稿ドロワー・アンサー投稿ドロワーと同じ言語に揃える。
- **相手を待たない。** ドロワーの中で6枚を一気に答えられる。「相手が答えるまで次に進めない」は**作らない**。
- **開封はカード1枚ごとに独立して判定する。** 両者がそのカードに答えた瞬間、そのカードだけが開く。
  - 例：自分が6枚すべて答えたあと、相手が1枚ずつ答えていくと、1枚ずつ順に開いていく。
- **自分の回答は最初から表示されている。** 伏せるのは**相手の回答だけ**。
  - 未開封の相手の行は、点線枠＋「回答まち」のマスク表示。
  - 開いた瞬間、その行だけがブラーから解けるアニメーション。
- **相手が何枚目を見ているかは表示しない。** 見せると急かしになる。見えるのは「そのカードに回答済みかどうか」だけ。

### なぜこうしたか（変更するとき用のメモ）

- 「回答」と「開封」は別のもの。回答は個人作業、開封は2人の事件。以前これを1本の鎖で繋いでいて、片方が詰まると全部止まった。
- ドロワーにしたのは、書いている最中に背後で相手の回答が届いても**画面が跳ねない**ようにするため。チャット＝2人の記録、ドロワー＝自分の作業台、と層を分ける。
- 同時開封にするのは、先に相手の答えが見えると忖度が生まれ、素の好みが歪むから。

## ② スタジオ枠の提案（ホスト）

### フロー

```
エリア選択（都道府県 → エリア）
   ↓
スタジオ選択（リスト or「その他（自分で入力）」）
   ↓
カレンダー（1ヶ月マス目）で日をタップ
   ↓
開始時刻（10:00〜22:00）＋ 利用時間（1h / 2h / 3h）→ 枠を追加
   ↓ ※最大3つまで
料金・店舗リンク（どちらも任意・空でも送れる）
   ↓
送信
```

### 仕様の要点

- 表示は「18:00〜20:00」に変換する。入力は**開始＋利用時間**（終了時刻は選ばせない。スタジオはパック料金なので人の頭の中の言い方に近い）。
- **枠は最大3つ。** 多いと選べない。3つ全滅なら「今週は縁がなかった」で次にいける。
- スタジオDBは **Step1では関西圏のみ**（大阪・京都・神戸あたりの主要エリア × 大手チェーン、数十件でよい）。
  - **「その他（自分で入力）」を必ず置く。** これが無いとリストに無い店で詰まる。
  - エリアは提携営業したところから増やす。関西で回る形が作れてから他地域に広げる。
- カレンダーは1ヶ月マス目。過去日は無効、土日を視覚的に強調、**枠を追加済みの日にはドット**を出す。

### 促しの出し分け（重要）

- **権限は2人とも持つ**（ゲストからも枠を出せる）。
- ただし**促すのはホストだけ**。
  - ホスト画面：目立つプライマリボタン「スタジオの空き枠を出す」
  - ゲスト画面：待ちの案内文＋**地味なテキストリンク**「自分から空き枠を出す」
- 理由：権限を配っただけでは誰も口火を切らず止まる。かといってホスト専用にすると乗り気なゲストが動けない。**促しは片方に、権限は両方に。**

---

## ③④ 選択と確定

- ゲストは枠を**1タップで選ぶだけ**。返信を打たせない。
- 選ばれた時点ではまだ**確定ではない**。
- ホストが実際にスタジオを予約し、**「スタジオを押さえた」ボタン**を押して初めて確定。
  - 「確定する」ではなく「押さえた」にしているのは、**2人とも合意したのに誰も予約していない**状態を防ぐため。当日行ったら部屋が無い、が最悪の事故。
- 確定後はカードの見た目を変える（枠線を赤系に、見出しを「✓ 予約できました」に）。

---

## つくらないもの

- **日付＋昼夜のざっくり候補（旧・第1段）は廃止。** デッキ6枚目と役割が重複し、往復が1回増えるだけだった。
- **「どれも難しい」ボタンは作らない。** 1対1なのでチャットで打てば済む。ボタンにすると断りの理由が消え、ホストの次の動きが分からなくなる。
- スタジオの空き情報の自動取得・スクレイピング。**空きはホストが自分で調べて手で入れる。**
- 場所の自動判定。5枚目は自由記述のままにして、**2人の回答を並べて見せるだけ**にする。
  - ただし**6枚目の時間帯だけは自動で突き合わせてよい**（選択式なので集合演算で確実に出せる）。「2人とも週末昼を選びました」の1行を出す。
  - 原則：**機械が言い切ってよいのは、絶対に外さないことだけ。** それ以外は材料を並べて、決めるのは2人に返す。

## 作業の進め方

### まずプランニングをする

1. 現在の実装を読む。**1対1の個別チャット部屋まではすでに動いている**ので、どこまでできているかを正確に把握する。
2. `prototypes/our-session-cards-v2.html` と `prototypes/our-session-studio.html` を確認し、今回足す挙動を把握する。
3. **既存の実装を絶対に崩さない。** 既存の画面・データ構造・命名を変える必要が出たら、勝手に手を入れず**先に報告**すること。

その上で実装プランを提示し、こちらの確認を取ってから着手すること。

### そのあと実装

- **色味や形状は現状の実装に合わせる。** プロトタイプの見た目をそのまま持ち込まず、既存の画面と揃えること。
- **動作はプロトタイプを確実に取り入れる。** `prototypes/our-session-cards-v2.html` と `prototypes/our-session-studio.html` の挙動を**正**とし、迷ったらそちらの実装を読むこと。

### 判断に迷ったら

勝手に決めず、先に質問すること。特に以下は**設計思想に直結する**ので独断で変えない：

- 「相手を待たせない」構造（回答と開封の分離）
- 「促しは片方に、権限は両方に」
- 「機械は材料を並べるだけ、決めるのは2人」
