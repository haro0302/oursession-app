# our-SESSION 改修指示書

添付の 2 ファイルが変更後の完成形です。これを正とし、実装側を合わせてください。

- `our-session-v27b-song.html` … タイムライン
- `our-session-profile.html` … プロフィール

このドキュメントは「何を変えたか」ではなく、**なぜそう変えたか**を書いています。
実装で判断に迷ったときは、この意図に沿う方を選んでください。

---

## 0. 前提となる思想

このサービスの結論は 3 つです。すべての変更はここから来ています。

1. **上手さは関係ない。同じ曲を合わせてみたいだけで成立する。**
   だから UI から「格付けに使える情報」を意図的に取り除く。

2. **主役は人ではなく曲。**
   「同じ曲が好きな人同士なら話が早い」が出発点。
   曲を主語にすると、出会い系的な「人を眺める」感覚が構造的に消える。

3. **投稿は全部タップで完結させる。**
   自由記述を必須にすると、書ける人が有利になり、書けない人が離脱する。

---

## 1. レベル表示を全廃した

### 変更

- プロフィール：アバター直下の `.lvl`（「練習中」）を削除
- タイムライン：カードデータの `level` と、展開時の `.dlevel` を削除

CSS（`.lvl` / `.dlevel`）は残してあります。復活させたくなったとき用です。

### 理由

二択・三択のラベルは、本人がどう思っていても **ランクとして読まれます**。
特にプロフィールでは、アバターの真下・名前の直前という最も目立つ位置にあり、
ページを開いた瞬間の第一情報が「初心者か経験者か」になっていました。

これは思想 1 と正面から矛盾します。

初心者であることを伝えたいなら、自己紹介文に自分の言葉で書けばいい。
**システムが貼るラベルと、自分で書いた文章では、受け取られ方がまったく違います。**

> ⚠️ 実装時の注意：レベルに類する項目（経験年数・習熟度・本気度など）を
> 他の画面に足さないでください。1 箇所でも残ると、この変更の効果が消えます。

## 2. 曲を構造化データにした

### 変更

カードのデータに `song` / `artist` を追加。
以前は曲名がタイトル文字列の中に埋まっていました。

```js
// 旧：曲名が自由テキストの中にある
title: 'ガンズの Knockin’ on Heaven’s Door、一緒にやりませんか'

// 新：独立したフィールド
song:   'Knockin’ on Heaven’s Door',
artist: 'Guns N’ Roses',
```

### 理由

**(a) JASRAC / NexTone への利用曲目報告**

音源は楽曲の演奏なので、報告対象です。
自由入力のままだと表記ゆれ（「マリーゴールド」「まりーごーるど」「Marigold」）で
名寄せが破綻します。**必ず楽曲マスタから選択させてください。**
Apple API での候補表示は実装済みとのことなので、選択結果をマスタに 1 行追加する形で。

**(b) 検索・絞り込みの軸になる**

曲名・アーティスト名でタイムラインを絞れるようにするための前提です。

**(c) 同じマスタを 2 用途で共用する**

| 用途 | 音源あり | 報告対象 |
|---|---|---|
| カードの曲 | あり | **対象**（再生回数を集計） |
| プロフィールの「やりたい曲」 | なし | 対象外 |

同じテーブルを引きますが扱いが違うので、
**DB 側に「報告対象かどうか」のフラグを持たせてください。** 後の集計が楽になります。

## 3. カードのタイトル入力を廃止した

### 変更

畳んだ行の構造をこう変えました。

```
[サムネ]  Knockin’ on Heaven’s Door   ← 16px / 600（曲名）
          Guns N’ Roses               ← 13px（アーティスト名）
```

- 旧：大きい行＝タイトル（自由記述）、小さい行＝「募集」「エリア」のチップ
- 新：大きい行＝曲名、小さい行＝アーティスト名
- タイトル欄そのものを廃止。書きたいことは**本文**へ

### 理由

**(a) 重複が消える**

以前は同じ情報が 2 回出ていました。

- 曲名がタイトルと本文の両方に
- 募集・エリアが畳んだ状態と開いた状態の両方に

読む側は毎回「これはさっき見たやつか？」を判断していたことになります。
畳んだ行を曲名だけにし、募集条件は展開時のみにしたことで、**重複がゼロになりました。**

**(b) 投稿のハードルが下がる**

タイトルを考えるのは、投稿で一番手が止まる作業です。
曲を選ぶだけで見出しが決まるなら、悩みようがない。
思想 3 のとおり、**必須項目が全部タップで済むようになりました。**

**(c) 出会い系的な印象が薄まる**

並んでいるのが「人の言葉」ではなく「曲」になると、画面の主語が変わります。
熱量のある文章で場を作ろうとすると、書ける人が有利になり、釣りの余地も生まれる。
曲＋音源なら、書いたことと弾いたことがその場で照合されます。

熱量は捨てていません。**本文と、リクエスト承認後の 5 問に移しただけ**です。
そこまで進んだ相手にだけ届く方が、純度は高い。

### オリジナル曲の扱い

アーティスト名の位置に `オリジナル曲` と表示します（ダミーデータに 1 件入れてあります）。
権利処理でカバーとオリジナルの区別は元々必要なので、仕様として自然です。

## 4. 「まだ練習中」を投稿単位のフラグにした

### 変更

アーティスト名の右にチップを表示。データは `wip: true`（任意）。

### 理由 ── 1 と矛盾しない設計にしてあります

一度消したレベル表示を戻したように見えますが、**紐づく対象が違います。**

| | 旧レベル表示 | 新「まだ練習中」 |
|---|---|---|
| 紐づく先 | **人**（プロフィール） | **投稿**（この曲） |
| 意味 | この人は初心者だ | この曲はまだ練習中だ |
| 性質 | ランク（比較できる） | 状態（比較できない） |

同じ人でも、弾き慣れた曲には付かず、練習中の曲には付きます。
だから **誰も上下にならない。** 全員が曲によって両方あり得ます。

役割は「未完成でも投稿していい」という**許可証**です。
「まだサビだけです」と出せることに意味がある、という設計思想の実装です。

> ⚠️ **プロフィール（人単位）には絶対に置かないでください。**
> 人に付けた瞬間、旧レベル表示と同じものに戻ります。

文言は「練習中」ではなく **「まだ練習中」** です。
「まだ」が入ると状態ラベルではなく本人の声になり、少し照れが混じって誘いやすくなります。

### レイアウト上の実装注意

長いアーティスト名（例：Earth, Wind & Fire）で崩れないよう、こうしてあります。

```css
.hart { flex: 0 1 auto; min-width: 0; text-overflow: ellipsis; }  /* 縮む */
.wip  { flex: none; white-space: nowrap; }                        /* 縮まない */
```

**狭い画面ではアーティスト名が「…」で省略され、「まだ練習中」は必ず残ります。**
逆にすると状態が消えるので、この優先順位は変えないでください。

## 5. プロフィールのタグ群を変更した

### 変更

| 旧 | 新 |
|---|---|
| パート・楽器 | パート・楽器 |
| ジャンル | **やりたい曲** ← 昇格・改名 |
| 好きなアーティスト | 好きなアーティスト |
| **好きな曲** | ジャンル ← 降格 |

- 大見出し「パートと好きな音楽」→「パートと音楽」
- セットアップカード：「やりたい曲を追加する / 同じ曲をやりたい人から見つけてもらえます」
- 「やりたい曲」のタグのみ `.tag.want` で枠線と地をわずかに強調

### 理由

**「好きな曲」と「やりたい曲」は意味がまったく違います。**

- 好きな曲 … 趣味の表明。聴き専の曲も入る。共感はできるが、**誘う理由にならない**
- やりたい曲 … セッションの候補リスト。実質、**募集内容**

「やりたい曲」がある人には、こちらから声をかける口実が生まれます。
ラベルを変えるだけで、プロフィールが「自己紹介」から「募集」に変わる。
**コストが低いわりに効果の大きい変更です。**

順序も、募集情報（やりたい曲）を上、趣味情報（ジャンル）を下にしました。
ジャンルが最も曖昧な情報なので最後です。

**「やりたい曲」も楽曲マスタから選ばせてください。** カードの曲と同じマスタです。
表記が揃っていないと、検索でカードとプロフィールが繋がりません。

## 6. プロフィールのセッションカードを統一した

プロフィール内のカードを、タイムラインと完全に同じ形にしました。
曲名 16px/600、アーティスト名 13px、「まだ練習中」チップ、展開時は募集パート/エリア/ジャンル。

### 理由

タイムライン・プロフィール・今後の検索結果で **同じ行を使い回せます。**
実装は 1 コンポーネントで済むはずです。ここは分岐させないでください。

## 7. 投稿フォームの仕様（この変更に伴う）

| 項目 | 必須 | 入力方法 |
|---|---|---|
| 曲 | ✅ | 楽曲マスタから選択（Apple API 候補） |
| アーティスト | ✅ | 曲の選択に付随 |
| 募集パート | ✅ | 選択 |
| エリア | ✅ | 選択 |
| ジャンル | ✅ | 選択 |
| 音源 | ✅ | アップロード |
| まだ練習中 | 任意 | トグル |
| 本文 | 任意 | 自由記述 |
| ~~タイトル~~ | — | **廃止** |

**必須項目はすべてタップで完結します。** 自由記述は本文のみ、それも任意。

### 本文のプレースホルダー

指示文（「例：〜について書いてください」）ではなく、
**そのまま真似できる完成した文章**を薄く入れてください。読み飛ばされにくくなります。

```
平日は21時以降、土日は昼から動けます。
まだ人と合わせた経験が少ないので、ゆっくり進めてもらえると助かります。
```

「まだ経験が少ない」の一文を含めているのは意図的です。
**それを書いていいと分かる**ので、レベル表示を消した代わりに、
自分の言葉で伝える場所ができます。
