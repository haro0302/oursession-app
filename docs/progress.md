## 設計判断のメモ

### 音源処理

- **ファイル形式**:
  - file-pick(ファイル選択): MP3 (`audio/mpeg`) のみ
  - recording(録音): m4a, webm, mp4, mpeg, ogg を許可(ブラウザの MediaRecorder 出力形式に対応)
- **ファイル長さ**: 90秒以下(クライアント側でチェック、サーバー変換しない)
- **ファイルサイズ**: 5MB 以下
- **エラー文言**: 温かく(「音源が少し長いようです(○分○秒)」)

### Supabase Storage

- **avatars バケット**: パブリック(getPublicUrl が永続的に使える)
- **avatars RLS**: SELECT 全員、INSERT/UPDATE/DELETE は自分のフォルダのみ
- **音源バケット**: プライベート + 署名URL(認証ユーザーのみ再生可能)

### DB

- **profiles**:
  - `nickname` は nullable(handle_new_user トリガーで空レコード作成のため)
  - `onboarded_at` で初回判定
  - **RLS**: SELECT 全員許可(JOIN クエリで他人のアバター取得に必要)
- **sessions**:
  - `author_id` を外部キーとして profiles と JOIN

### UI パターン

- **タグ選択**: フィルタシート方式で統一(投稿 / プロフィール編集 / タイムラインフィルタ)
- **アーティスト・曲**: 「+追加」個別タグ追加方式
- **フローティングナビ**: 統一スタイル(投稿だけ赤丸の特別扱いはしない)
- **ドロワーアニメ**: always-in-DOM + transform translateY(消すとアニメしない)
- **オーバーレイ z-index**:
  - 100: Toast(最前面)
  - 95: オフライン画面
  - 85: ドロワー(アンサー投稿・プロフィール編集・認証)
  - 80: オンボーディング
  - 70: オーバーレイ(プロフィール・設定・保存一覧・通知)
  - 66: シート(通報・フィルタ・アクション)
  - 50: フローティングナビ

### アバター

- **自分のアバター**: profileStore で全画面同期
- **他人のアバター**: Supabase JOIN で取得(常に最新)
- **共通 Avatar コンポーネント**: サイズバリアント(sm: 24px / md: 38px / lg: 56px / xl: 96px)
- **注意**: 他人プロフィールオーバーレイには profileStore を使わない(profileStore は自分専用)。他人の profiles を都度 fetch すること。
- **アバタータップ**: 自分なら `/mypage` 遷移、他人ならオーバーレイ表示

### カードアクション

- **他人カード**: ⋯ → 「通報」「ブロック」
- **自分カード**: ⋯ → 「編集」「削除」
- **編集の音源**: 変更不可(投稿の核心は変えない。変更したいなら削除して新規投稿)
- **編集の URL**: `/post?edit=セッションID` で投稿ページを編集モードで開く
- **権限チェック**: 編集・削除は本人のみ。SELECT・UPDATE 両方で `author_id = auth.uid()` を確認
- **通報**: `reports` テーブルに保存。MVP では運営者が Supabase で目視確認

### 認証

- **Magic Link**: 残す(Google アカウント持ってない人向け)
- **Google ログイン**: メイン(タブ問題なし、3秒でログイン)
- **Apple ログイン**: MVP では保留(Apple Developer $99/年が必要)

## ⚠️ 重要なルール(Claude Code 向け)

新しい修正をする時は、以下を必ず守ること:

1. **既存の実装を尊重する** - 「動いている部分」を勝手に壊さない
2. **仕様書を参照する** - `docs/specs/` 配下に画面別の仕様書あり
3. **CLAUDE.md の方針に従う** - コピー、トーン、デザイントークン
4. **インラインスタイルを書かない** - 必ず CSS クラス + CSS変数
5. **DB スキーマ変更は手動承認** - ヨシキさんに SQL を提示、勝手に実行しない
6. **読めた確認をする** - 仕様書を Read した後、内容について質問に答える
